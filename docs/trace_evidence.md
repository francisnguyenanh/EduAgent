# Google Cloud Trace Evidence: End-to-End Distributed Telemetry

> **Observability Architecture:** The end-to-end flow from initial student essay submission to class-wide synthesis is instrumented with distributed OpenTelemetry spans exported directly to **Google Cloud Trace & Cloud Logging**.
>
> ⚠️ **Data Source Transparency Note (Audit Wave 11):** The spans, execution sequence, and attributes detailed below are generated by `scripts/export_trace_evidence.py::simulate_traced_pipeline()`—which uses timed sleep stubs (`time.sleep(0.015)`, etc.) to **illustrate the structural span hierarchy** (root → intake → sanitizer → summarizer → persona → debate → scorer → aggregator) produced by our production instrumentation (`src/eduagent/tracing.py`, `@traced_node` decorator on all 8 graph nodes). **The millisecond figures below are NOT actual live Gemini API latencies** (a live Gemini Flash round-trip typically takes 0.5–3.0s, not 45ms or 124ms for a 3-turn debate). Treat this document as **structural proof of correct telemetry instrumentation and span hierarchy**, not as an absolute performance benchmark. For live production latencies, submit an essay on the live Cloud Run deployment and open **Cloud Trace → Trace Explorer** in the Google Cloud Console, filtered to the `eduagent-class-aggregator` service. A captured example of that view is committed at `assets/gcp_evidence/Cloud Trace span end-to-end.png`.

* **What this verifies:** Verified parent-child span hierarchy (the debate loop contains nested spans for each turn), node execution sequencing, and accurate OpenTelemetry attribute emission from actual node states.
* **What is NOT claimed:** That end-to-end LLM processing takes ~250ms; actual live latency depends on Vertex AI generation time.
* **Trace Standard:** W3C Trace Context (`traceparent` header propagation across microservices).

## 3. Structured Cloud Logging Integration

All Cloud Run log entries automatically correlate with Trace IDs via the `logging.googleapis.com/trace` field.

> ⚠️ **The block below is an ILLUSTRATIVE record showing the shape of the correlation, not a
> captured log line.** Its project id, trace id, and `students_ranked` value are placeholders chosen
> to make the structure readable — do not read `12` as a measurement of any class in this project
> (the seeded demo class `c1` has seven students), and do not expect that project id to resolve.
> It is kept as an illustration rather than swapped for a real capture on purpose: this document's
> whole premise is that structural evidence must not be dressed up as measured evidence. For a real
> correlated entry, open **Cloud Logging** on the deployed revision and expand any `eduagent.*` JSON
> payload. (`assets/gcp_evidence/Log.png` is *not* that: it captures the Cloud Run request log, not
> an expanded structured payload — it is listed here so the distinction is not left to the reader.)
